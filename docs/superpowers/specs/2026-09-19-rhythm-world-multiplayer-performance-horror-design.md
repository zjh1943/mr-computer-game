# 我的节奏盒子世界：联机、演出与布莱克事件设计

日期：2026-09-19

## 目标

在现有的 2D Sprunki 角色、3D 无限小镇基础上，完成三个相互衔接但可以独立验证的子系统：

1. 修复角色合唱没有声音、没有表演动作，以及夜间演唱会角色不到场、太阳运行错误的问题。
2. 让最多 20 名玩家自动进入同一个小镇，实时看到彼此、自由聊天并一起唱歌跳舞。
3. 增加可关闭、极少发生的布莱克第二阶段事件，营造阴森但不血腥的变化。

游戏页面继续由 GitHub Pages 提供，不发布到 ChatGPT Sites。联网服务只负责实时消息，不接管网页托管。

## 已确认的玩家体验

- 玩家打开游戏后照常进入小镇，不显示“公共小镇”、房间号或选房界面。
- 每个小镇最多容纳 20 名真人玩家。小镇满员时，系统在后台自动分配到下一个相同小镇。
- 玩家可以自由输入聊天文字；消息同时出现在顶部聊天框和说话角色头顶的临时气泡中。
- 真人、NPC 和太阳公公在唱歌时必须有可见动作、嘴型和实际声音。
- 夜间演唱会开始前，NPC 会从自己的家前往音乐广场；演出结束后回家。
- 太阳公公白天沿天空弧线运行，落山时告别；夜晚下班后才能飞到广场参加演出。
- 布莱克的异常事件约每 30 至 40 分钟才获得一次触发机会，并受“布莱克是否变坏”设置控制。

## 范围分解与实施顺序

### 第一阶段：演出基础修复

先修复声音、动画、NPC 路径和太阳天空路径。这是后续联机同步的可靠本地状态来源。

### 第二阶段：20 人实时联机

在本地演出状态稳定后，同步玩家、聊天和合唱。离线时仍保留完整单人玩法。

### 第三阶段：布莱克稀有事件

最后加入由服务器统一决定的世界事件，避免不同玩家看到不同的日夜、角色形态或事件阶段。

## 系统架构

### 网页端

GitHub Pages 继续托管 `rhythm-world.html`、脚本、样式、角色图片和音频素材。网页端负责：

- 3D 场景和 2D 角色渲染；
- 本地输入、摄像机和碰撞；
- 音频播放与兼容性降级；
- 远程玩家插值显示；
- 聊天、邀请和连接状态界面；
- 单人离线回退。

### 实时服务

使用 Cloudflare Worker 和 Durable Objects 提供 WebSocket 中继。每个 Durable Object 实例代表一个最多 20 人的小镇分片，维护：

- 在线玩家及其角色占用；
- 最近一次合法的位置、朝向和动作；
- 日夜与演唱会状态；
- 合唱成员和邀请；
- 布莱克事件状态；
- 临时聊天广播，不保存永久聊天记录。

分片名只在服务端使用，例如 `town-0`、`town-1`。玩家界面始终只显示“小镇”。前端通过一个独立配置常量连接 Worker；配置缺失或服务不可达时自动进入单人模式。

## 演出与音频设计

### 已查明的现有故障

当前内置浏览器中 `AudioContext` 和 `speechSynthesis` 均不可用。旧的合唱入口先改变了合唱状态，随后在直接访问 `AudioContext` 时抛错，使声音和后续动作不完整。NPC 的普通逐帧运动也没有正式的“表演”状态，夜间舞台则只渲染面板头像，并未驱动小镇 NPC 前往广场。太阳绑定在摄像机下，因此它不是小镇空间中的真实天空对象。

### 音频能力层

建立统一音频接口，启动时检测能力，按以下顺序选择：

1. 可用时使用 Web Audio 合成并混合角色音轨；
2. Web Audio 不可用时使用预先准备的短循环音频元素；
3. 若音频播放被浏览器阻止，显示一次“点击开启声音”提示，并在下一次玩家手势后重试；
4. 完全无法播放时仍运行动画和节拍，不让交互流程因异常中断。

每位角色拥有独立的音色、节奏型和音量包络。所有参与者共享节拍时钟，加入时从下一小节开始，退出时在小节边界淡出，避免声音突然断裂。

### 表演状态

角色状态机增加 `performing`，与 `idle`、`walking`、`speaking` 分离。表演包含：

- 角色专属点头、摇摆、弹跳或配件动作；
- 按音符开合的嘴型；
- 偶尔闭眼、互相注视；
- 一起跳舞时的同步节拍，但保留不同角色的动作个性。

合唱按钮启动后，玩家、领唱 NPC、获准加入的第三位角色及自动加入者都进入 `performing`。点击“结束唱歌”后，音轨淡出、动作回到空闲，按钮恢复为邀请入口。

### 夜间音乐广场

音乐广场是小镇中的实体地点，不再只是覆盖世界的舞台面板。夜晚临近演出时：

- 可参加的 NPC 从家门口沿路径走向各自站位；
- 电脑先生有电时飞往广场，低电时先返航充电；
- 演出开始后，小镇镜头仍可移动，玩家可以围观或加入；
- 结束后 NPC 离场回家。

舞台界面若保留，只作为选音色和开始演出的控制面板，不遮挡整个小镇。

### 太阳与月亮

太阳和月亮属于世界空间的天空层，不附着在摄像机上。它们从地平线升起，沿长弧线经过天空后落到另一侧。天空层使用独立深度策略保证不被房屋遮住，同时保持方向随玩家观察角度一致。

太阳落山前说“再见了，朋友们，我要走啦！”。夜间演唱会开始后，太阳从落日方向飞到音乐广场的空中站位，加入音轨和舞蹈；白天仍在工作时不能参加。

## 多人联机设计

### 进入与身份

玩家首次连接时创建本地随机 ID，并发送所选角色、显示名和初始位置。默认显示名为“角色名＋随机编号”。服务器把玩家放入第一个未满 20 人的小镇。

同一个小镇内真人玩家不能选择相同角色。角色被占用时，角色选择界面明确标记“这个角色正在小镇中”，玩家需要改选。NPC 不参与真人角色占用，也不计入 20 人上限。

### 同步消息

位置、朝向和动作以约每秒 6 至 8 次发送。服务端验证后以约 100 毫秒批次广播。接收端保存目标状态并插值显示，避免移动一卡一卡。

同步动作包括：

- 空闲、行走和朝向；
- 说话和聊天气泡；
- 唱歌、舞蹈及所用角色音轨；
- 合唱邀请、同意、拒绝和退出；
- 日夜、演唱会与布莱克事件阶段。

客户端不得直接决定全局日夜或布莱克事件，只能显示服务器发布的世界状态。

### 自由聊天

顶部增加可收起的聊天框，显示最近消息、在线人数、输入框和发送按钮。

- 每条消息最多 80 个字符；
- 去掉空消息、控制字符和不可见刷屏内容；
- 始终使用纯文本渲染，不解析 HTML；
- 限制发送频率，允许短时间少量连续发送，但持续刷屏会暂时冷却；
- 每位玩家提供本地“静音”功能；
- 不保存永久聊天历史，新加入者只收到加入后的消息。

发送消息时，角色看向附近玩家、播放嘴型，头顶气泡短暂出现。文字聊天不依赖系统文本朗读，因此不支持语音合成的浏览器仍可正常使用。

### 多人合唱

靠近真人或 NPC 时显示“一起唱歌”。邀请真人时，对方看到“同意”和“不同意”：

- 同意：双方在下一小节开始演奏，动作和声音向全镇广播；
- 不同意：邀请结束，对方角色离开合唱靠近状态；
- 第三人可申请加入，同样需要现有合唱发起者确认；
- NPC 可以依照距离和空位自动申请加入；
- 停止合唱会清除所有成员音轨和表演状态。

## 布莱克稀有事件

### 正常形态

布莱克为黑色圆脸身体，戴黑色礼帽和白色领结，具有可见眼睛和白色嘴部。正常状态下他和其他 NPC 一样活动、说话和演奏。

### 触发规则

设置增加“布莱克是否变坏”，默认关闭。开启后：

- 世界至少连续运行 30 分钟才进入首次检查窗口；
- 此后每 30 至 40 分钟产生一次低概率检查；
- 同一小镇由服务器进行一次判定，所有玩家看到相同结果；
- 演唱会、角色创建和新手流程中不触发；
- 事件结束后有更长冷却，避免连续发生。

### 阶段变化

事件分为预兆、转化、第二阶段和恢复：

1. 预兆：音乐轻微走调，布莱克停止移动，天空逐渐变暗。
2. 转化：布莱克变得更高、身体凹陷，脸部成为藏在阴影里的双色怪异面孔，声音变为失真的环境音。
3. 第二阶段：主要角色逐个切换到各自的阴森形态，动作与音轨发生变化。
4. 恢复：画面、角色和音乐逐步回到正常小镇。

表现重点是诡异、阴影、失真、异常动作和紧张音乐，不使用流血、肢解或写实伤害画面。设置菜单提供“立即结束异常事件”，方便不喜欢恐怖内容的玩家恢复世界。

## 校验、安全与容错

实时服务不信任客户端提交的数据：

- 丢弃非有限坐标、超速移动、过大消息和未知动作；
- 限制位置包、聊天和邀请频率；
- 拒绝重复角色占用；
- 聊天只广播清理后的纯文本；
- 玩家断线后立即释放角色占用并通知其他客户端淡出角色。

连接断开时显示“正在重新连接”，使用指数退避重试。玩家仍可在本地移动并使用单人内容，但断线期间不伪造其他在线玩家。重连成功后以服务器快照重新对齐，不回放过期位置包。

若 Worker 未配置、额度用尽或服务不可达，游戏自动进入单人模式，封面、存档和本地小镇仍可正常使用。

## 模块边界

前端新增或拆分为以下职责明确的模块：

- `audio-capabilities`：检测并选择音频实现；
- `performance-state`：计算角色表演、嘴型和节拍动作；
- `concert-world`：管理 NPC 集合、走位、演出和退场；
- `multiplayer-client`：WebSocket 生命周期和消息协议；
- `remote-players`：远程角色创建、插值和移除；
- `town-chat`：聊天界面、气泡、静音和本地校验；
- `black-event`：布莱克事件状态机与视觉/音频阶段；
- `world-clock`：由单机或服务器状态驱动日夜与天空路径。

Worker 工程单独放置，包含连接分配、Durable Object 小镇实例、协议校验、限流和世界事件时钟。前后端通过带版本号的 JSON 消息协议通信，未知消息可安全忽略。

## 测试与验收

### 自动化测试

- 音频能力选择和不支持 Web Audio 时的降级；
- 表演状态不会被普通 NPC 更新覆盖；
- 合唱开始、第三人加入、拒绝和结束状态；
- NPC 前往广场、站位和回家；
- 太阳天空弧线、落山告别及仅在夜间加入演出；
- 玩家分片分配、20 人上限和角色唯一占用；
- 位置包校验、插值、掉线移除和重连快照；
- 聊天长度、纯文本清理、限流和静音；
- 布莱克设置关闭时绝不触发，开启后仍遵守时间窗口和冷却。

### 集成测试

使用 2 至 20 个模拟 WebSocket 客户端验证加入、移动、聊天、合唱和断线。两个真实浏览器标签页分别选择不同角色，确认双方能看到平滑移动、气泡、声音和舞蹈。

### 人工验收

在电脑、手机尺寸和平板尺寸测试：

- 打开页面可直接进入小镇，不出现房间选择；
- 合唱始终有声音或明确的开启声音提示，且角色有明显动作；
- 顶部聊天框不遮挡摇杆、互动和一起唱歌按钮；
- 舞台不挡住小镇；
- 太阳始终在天空层，夜晚由月亮替代，并能在夜间演唱会飞来；
- 20 人情况下仍可移动、聊天和跳舞；
- 布莱克事件稀少、可关闭、可立即恢复，且不包含血腥表现。

## 不在本轮范围

- 账号注册、好友系统和私人房间；
- 永久聊天记录或跨小镇私聊；
- 玩家交易、付费内容和排行榜；
- 语音通话；
- 依靠客户端模拟出来的假在线玩家。
